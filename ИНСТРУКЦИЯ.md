# BIORYX: установка тестового магазина без терминала

## Что получится и важные ограничения
GitHub Pages хранит сайт, Cloudflare Worker принимает заказы, Cloudflare D1 хранит каталог и заказы. Telegram доставляет владельцу уведомления; покупательский бот пока отвечает на /start и ведёт в каталог. Предоставленный код — тестовый контур, не полный аналог RULES: личный кабинет, клуб, CRM, отслеживание заказов в боте, авторасчёт и создание отправлений СДЭК, автоматическое подтверждение СБП отсутствуют. Покупатель сообщает адрес или ПВЗ, вы согласуете стоимость доставки и перевод лично. Наличные разрешены только при самовывозе и доставке курьером по Грозному. Демо-товары, цены и изображения ненастоящие.

Не публикуйте витрину для настоящих клиентов до проверки безопасности, обработки персональных данных, документов магазина, порядка оплаты/доставки и тестирования. В текущей версии нет защиты от спама, кабинета администратора, отмены заказа и возврата остатков. Уведомления могут дублироваться при повторной доставке; при статусе неуспеха платежа товары не отгружаются автоматически.

## 1. Подготовка файлов
1. Скачайте архив проекта и распакуйте. Внутри — папка `bioryx`. Открывать файлы для копирования можно обычным текстовым редактором (Блокнот), не Word.
2. Создайте **новый** публичный репозиторий GitHub, например `bioryx`. Не используйте репозиторий RULES. Нажмите Add file → Upload files и загрузите содержимое папки `bioryx` в корень репозитория. В корне должны оказаться `index.html`, `catalog.html`, папки `assets`, `data` и т. д., а не вложенная папка `bioryx`.
3. Settings → Pages → Build and deployment → Deploy from a branch → main / (root) → Save. Дождитесь ссылки Pages и откройте её. Адрес обычно `https://ВАШ-ЛОГИН.github.io/bioryx/`. Пока сайт работает в локальном демо-режиме.

## 2. Новая база Cloudflare D1
1. В Cloudflare откройте Storage & databases → D1 SQL Database → Create database. Создайте новую базу, например `bioryx-db`. **Не выбирайте старую базу RULES!**
2. Откройте новую базу → Console. Откройте файл `worker/setup.sql`, скопируйте весь текст, вставьте в Console и нажмите Execute. Если интерфейс не позволяет выполнить всё разом, выполняйте по отдельности полные SQL-операторы по порядку из трёх файлов в `worker/migrations/`. Блок `CREATE TRIGGER ... BEGIN ... END;` — один оператор, его нельзя делить по внутренним `;`.
3. Для проверки выполните `SELECT id, name, price, stock FROM products;` — должно быть 6 демонстрационных товаров. Создание SQL-таблиц работает только для новой BIORYX-базы.

## 3. Создайте двух Telegram-ботов
1. В Telegram откройте официальный @BotFather → /newbot. Создайте **отдельного** бота для уведомлений владельца и сохраните токен.
2. Создайте второго бота для покупателей и сохраните его токен. Откройте обоих ботов в Telegram и нажмите Start; особенно важно отправить /start владельческому боту с вашего личного аккаунта.
3. Никому не отправляйте токены, не сохраняйте их в GitHub. Если токен утёк — перевыпустите его через BotFather.

## 4. Создайте Worker и подключите базу
1. В Cloudflare → Workers & Pages → Create application / Create Worker создайте Worker, например `bioryx-api`. Запишите выданный HTTPS-адрес `https://ИМЯ.УЧЁТНАЯ-ЗАПИСЬ.workers.dev` без завершающего `/`.
2. Откройте Worker → Edit code. Полностью замените исходный код содержимым `worker/src/index.js` и нажмите Deploy. Не вставляйте туда токены.
3. Worker → Settings → Bindings → Add binding → D1 database. Имя переменной **DB**, база — `bioryx-db`. Сохраните и при необходимости выполните Deploy новой версии. Названия кнопок могут немного отличаться в зависимости от интерфейса Cloudflare.
4. Settings → Variables and Secrets добавьте:
   - `SITE_URL` — обычная текстовая переменная: полный адрес сайта GitHub Pages **с завершающим слэшем**, например `https://username.github.io/bioryx/`;
   - `OWNER_BOT_TOKEN` — Secret, токен бота владельца;
   - `CUSTOMER_BOT_TOKEN` — Secret, токен бота покупателя;
   - `WEBHOOK_SECRET` — Secret, самостоятельно придуманный длинный случайный секрет (только латинские буквы, цифры, `_` и `-`); это не токен бота;
   - `SETUP_SECRET` — Secret, другой длинный случайный пароль для временной страницы настройки (не менее 32 случайных символов).
   После изменений сохраните и разверните версию Worker, если интерфейс этого требует. `OWNER_CHAT_ID` добавим на следующем шаге.
5. Откройте в браузере `АДРЕС-WORKER/health`. Должен появиться ответ с `"ok":true` и `"db":true`. Затем откройте `АДРЕС-WORKER/catalog` и убедитесь, что видите JSON с товарами. `db:true` означает наличие привязки, но не полную проверку базы.

## 5. Настройка Telegram
1. Убедитесь, что отправили /start владельческому боту с нужного личного Telegram-аккаунта.
2. Откройте `АДРЕС-WORKER/setup`. Введите `SETUP_SECRET`, нажмите «Узнать chat ID владельца». В выдаче найдите свой личный чат и скопируйте его `id`. Если список пуст — заново отправьте боту /start и повторите; у нового бота владельца не должен быть установлен webhook. Это личная страница настройки, не сообщайте пароль посторонним.
3. В Variables and Secrets Worker добавьте `OWNER_CHAT_ID` как текстовую переменную со скопированным числовым ID (можно как Secret), сохраните/разверните Worker.
4. Вновь откройте `/setup`, введите SETUP_SECRET и нажмите «Подключить клиентского бота». Должно появиться `"ok": true`. Откройте клиентского бота и отправьте /start — он должен показать приветствие и ссылку на сайт.
5. После настройки **удалите `SETUP_SECRET` из переменных Worker и разверните изменение**, чтобы отключить действия на странице настройки. Для ручного повторного запуска очереди можно временно добавить новый случайный SETUP_SECRET, выполнить действие и снова удалить. Не используйте простые пароли.

## 6. Подключите сайт к Worker
1. В GitHub откройте `assets/config.js` → значок карандаша Edit.
2. Вместо пустой строки укажите адрес Worker, например:
   `window.BIORYX_API = 'https://bioryx-api.example.workers.dev';`
   Здесь пример адреса — замените своим. Commit changes и дождитесь новой публикации Pages.
3. Откройте сайт по фактическому адресу из `SITE_URL` (не по локальному файлу). Каталог загрузится из D1; добавьте демонстрационный товар и отправьте тестовый заказ. Приём из другой доменной зоны заблокирован CORS; если меняете домен сайта, обновите SITE_URL в Worker и перепроверьте.

## 7. Очередь уведомлений
Worker пытается отправить уведомление сразу после создания заказа. При ошибке оно остаётся в outbox. Добавьте Cron Trigger в настройках Worker (Triggers → Cron Triggers), например `*/5 * * * *`, чтобы повторять попытки каждые 5 минут. Если интерфейс просит выбрать обработчик, используется экспортированный `scheduled`. Альтернатива — временно включить SETUP_SECRET и на `/setup` нажать «Повторить уведомления». При сбоях между отправкой и записью статуса возможно повторное сообщение — сверяйте ID заказа.

## 8. Проверка перед дальнейшей работой
- Проверьте все три варианта доставки, наличные для самовывоза и курьера; для СДЭК вариант наличных должен быть недоступен.
- Проверьте заказ и уведомление Telegram, убедитесь, что сумма товаров и телефон верны, что остаток уменьшился в D1, и что при нулевом остатке товар нельзя заказать.
- Проверьте повтор при временном отключении Telegram, привязку D1 и клиентского бота, мобильный экран и доступ к GitHub Pages.
- В D1 Console можно посмотреть тестовые заказы запросом `SELECT id, created_at, status, total FROM orders ORDER BY created_at DESC;`. Данные клиентов не публикуйте.
- При реальном запуске замените тестовые товары, изображения и цены, добавьте правила, реквизиты, политику обработки данных, безопасность и поддержку; отдельно реализуйте оплату, СДЭК и лояльность. Тестовая система не заменяет юридическую и техническую проверку.

## Частые проблемы
- Сайт показывает только демо: проверьте `assets/config.js` и дождитесь публикации GitHub Pages.
- Каталог недоступен: проверьте binding `DB`, создание схемы и SITE_URL; попробуйте `/catalog` в браузере.
- Заказ не отправляется: проверьте именно опубликованный домен SITE_URL, сеть, доступность Worker и наличие товаров; подробные ошибки смотрите в Cloudflare Worker Logs без публикации личных данных.
- Нет уведомлений: проверьте токен владельческого бота, OWNER_CHAT_ID и что нажали Start, затем повторите очередь. Не путайте ботов.
- Потерян SETUP_SECRET: задайте новый в Cloudflare, выполните действия, затем удалите секрет.
